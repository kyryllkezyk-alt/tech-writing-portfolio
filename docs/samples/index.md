# Writing samples

Each sample targets a different reader and a different moment in that reader's work. The table
lists what each one is meant to show.

| Sample | Genre | Reader | What it demonstrates |
| --- | --- | --- | --- |
| [Quickstart](quickstart.md) | Tutorial | New developer | Time-to-first-success, one path, verifiable steps |
| [REST API reference](api-reference.md) | Reference | Integrating developer | Complete, scannable, consistent endpoint structure |
| [Right-to-left text](rtl-guide.md) | How-to | Front-end developer | Task focus, prerequisites, edge cases |
| [Translation memory leverage](translation-memory.md) | Concept | Product manager | Explaining a mental model without a procedure |
| [Release notes 4.0](release-notes.md) | Release notes | Existing customer | Breaking changes with a migration path |
| [Troubleshooting imports](troubleshooting.md) | Troubleshooting | Support engineer | Symptom-first indexing |
| [Stuck job queue](runbook.md) | Runbook | On-call engineer | Decision points under pressure |

## The product

**Lingua** is a fictional cloud platform that stores source strings, routes them to translators,
applies translation memory, and returns localized files to a customer's repository.
