# Documentation for a distributed linguist network

**Role:** Division manager · **Area:** Contributor onboarding and process docs · **Deliverable:**
Knowledge base, onboarding path and templates

## Situation

I managed a large network of freelance Hebrew linguists working across time zones, clients and
tools. Instructions lived in email threads, chat messages and the memory of a few senior people.

## Problem

- New linguists asked the same questions every week.
- Client-specific rules conflicted and nobody knew which version was current.
- Quality varied by who had onboarded whom.

## What I did

1. **Audited the questions.** I collected a month of linguist questions and grouped them by topic.
   A small number of topics covered most of the volume.
2. **Built a knowledge base** with one page per client and one page per recurring task, each with
   an owner and a last-reviewed date.
3. **Created an onboarding path:** a checklist, a test task with an answer key, and a feedback
   template.
4. **Standardized templates** for query sheets and delivery notes, so project managers could
   process them without reformatting.
5. **Set a review cadence.** Every page was reviewed when its client's guidelines changed, and at
   least quarterly.

## Outcome

- Repeated questions fell significantly once the knowledge base was the first stop.
- New linguists reached production quality faster.
- Client rule conflicts surfaced in one place and were resolved instead of rediscovered.

## What this shows

Information architecture and ownership matter as much as the writing. A page without an owner is
out of date by next quarter.
